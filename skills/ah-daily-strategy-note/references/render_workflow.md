# Render Workflow

这个 reference 用来锁定 `ah-daily-strategy-note` 从信息获取到 HTML、再到 PDF 的落地流程。
目标不是讲通用前端，而是避免这类策略页反复踩同一批坑：

1. 交易日口径写错
2. HTML 做成固定纸张壳子
3. PDF 导出时触发移动端断点
4. 屏幕版和打印版显示不一致

## 总流程

固定按下面顺序执行：

1. 确认真实交易日期
2. 整理结构化输入
3. 生成 Markdown 成稿
4. 基于同一份内容生成 HTML
5. 先在屏幕版检查层级、颜色、密度
6. 再切换打印样式导出 PDF

不要跳过 HTML 直接从 Markdown 生成最终 PDF。

## 1. 信息获取

- 用户说“最新 / 今天 / 盘后 / 明天”时，先确认真实日期
- 若当天不是交易日，默认写“最新完整交易日”
- 指数、板块、个股行情先用市场数据源
- 宏观、政策、盘后变量用新闻源补解释
- 页脚必须写清数据口径与绝对日期

最低核对项：

- 上证
- 深证
- 创业板
- 恒生
- 恒生科技
- 宏观驱动
- 政策驱动
- 盘后变量

## 2. Markdown 成稿

- 先按 `report_schema.md` 组织，再落正式 Markdown
- Markdown 是唯一内容源
- HTML 和 PDF 都必须从同一份 Markdown 演绎，不要各写各的

## 3. HTML 生成原则

默认输出“正常阅读版 HTML”：

- 屏幕阅读优先
- 容器宽度可控，但不要写死成 A4 高度
- 字号按正常系统阅读大小，不要为了塞一页把正文压到 10px 附近
- 页面可以自然变长

默认不要：

- `height: 297mm`
- `min-height: 297mm` 配合强纸张壳子
- 把整个页面做成单张固定纸面再截图式导出

推荐：

- 用单一主容器控制最大宽度
- 屏幕样式与打印样式分开维护
- 同一份 HTML 同时服务浏览和打印

## 4. 屏幕版样式

屏幕版负责：

- 正常阅读体验
- 合理留白
- 桌面端多栏布局
- 移动端单栏折叠

移动端规则必须限制在：

- `@media screen and (max-width: ...)`

不要写成不带 `screen` 的宽度断点，否则打印成 PDF 时也会触发移动端单列布局。

## 5. 打印版样式

打印版负责：

- A4 宽度自适应
- 多页分页
- 保持和屏幕版尽量一致的内容层级

打印时的原则：

- 用 `@media print` 单独接管排版
- 按 A4 可用宽度重新定义网格
- 指数区、双栏区、底部区都要根据 A4 宽度做紧凑布局
- 尽量使用 `break-inside: avoid` 保护卡片不被拦腰切开

推荐打印策略：

- 指数区：`3` 列
- A股 / 港股核心分析：`2` 列
- 微观动态：`2` 列或 `3` 列，按密度调整
- 新闻与策略：`2` 列

## 6. PDF 导出

默认用浏览器打印链路，而不是重新排版：

- 浏览器打印
- Playwright + Chromium

原因：

- 可以直接复用 HTML 与 CSS
- 屏幕版和打印版的一致性更高
- 不需要把 HTML 内容再翻译成另一套 PDF 组件

不要优先用：

- `reportlab` 重新手写排版 HTML 内容

这会造成：

- 样式重复维护
- HTML 与 PDF 不一致
- 调整一次布局要改两套实现

## 7. 单长页模式

只有用户明确要求“单长页 / 不分页 / 长截图式 PDF”时才使用。

此时要额外处理：

- 去掉 A4 页面壳子
- 不使用固定纸张高度
- 先测量实际内容高度
- 再按同宽同高导出单页 PDF

否则就会出现：

- 长画布里嵌一张 A4 页面
- 页面上半或下半出现大块空白

## 8. 最终检查

导出前至少检查：

- 日期是否是最新完整交易日
- 指数区是否仍是紧凑多列，而不是每张卡一整行
- 标签颜色是否遵循 A股红涨绿跌
- PDF 是否误触发移动端断点
- HTML 与 PDF 的内容顺序是否一致
- 页脚是否写清来源与口径
